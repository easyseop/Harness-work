# internal-solution 채우기 키트

MVP 하네스 **internal-solution**(내부 시스템 연동)을 완성하기 위한 키트입니다.
모르는 용어는 `GLOSSARY.md`(용어풀이)를 보세요.

## 이 하네스가 하는 일 (한 줄)

> 쪽지·내부 API·파일전송 같은 **내부 시스템에 연결해야 하는 기능**을, 외부망에서는 실제 정보 없이
> "민감정보 없는 약속(계약)과 가짜 대체물(대역)"으로만 다루게 만든다.

이렇게 해야 외부망에 내부 비밀이 새지 않고(규칙 5), 내부로 들여온 뒤 코드를 거의 안 고쳐도 된다.

## 왜 필요한가 (쉽게)

외부망에서 개발하다 보면 "사내 쪽지로 알림 보내기" 같은 기능이 필요할 때가 있습니다.
이때 **실제 쪽지 서버 주소나 접속 정보를 외부망에 적으면 큰 사고**입니다.
그래서 외부망에는 "무엇을 넣으면 무엇이 나온다"는 **약속(계약)** 만 두고,
진짜 연결은 내부망에서 붙입니다. 이 키트가 그 약속을 안전하게 적는 양식입니다.

## 폴더 안에 뭐가 있나

| 파일 | 누가 | 설명 |
|---|---|---|
| `solution-card.template.yaml` | 🟡 당신/담당자 | 내부 시스템 1개를 적는 **카드 양식** |
| `solution-card.example.yaml` | 🟢 예시 | 쪽지 시스템을 안전하게 적은 샘플 |
| `solution-card.schema.json` | 🟢 | 카드 형식 자동 검사 규칙 |
| `gates/check-no-internal-secrets.sh` | 🟢 | **실제 주소·비밀번호가 섞였는지 검사** (가장 중요) |
| `gates/check-contract-complete.sh` | 🟢 | 카드에 빈칸이 없는지 검사 |
| `manifest.yaml` | 🟢 | 하네스 자기소개 파일 |
| `FILL-GUIDE.md` | (읽기) | 카드 채우는 설명서 |
| `SAFE-OR-NOT.md` | 🔴 (읽기) | 안전수칙 — 먼저 읽으세요 |

## 쓰는 순서

```text
1. SAFE-OR-NOT.md 를 먼저 읽는다 (절대 적으면 안 되는 것)
2. FILL-GUIDE.md 를 보며
3. solution-card.template.yaml 을 복사해 내부 시스템 1개당 카드 1장을 채운다
4. 검사를 돌려 실제 주소·비밀번호가 안 섞였는지, 빈칸이 없는지 확인한다
```
