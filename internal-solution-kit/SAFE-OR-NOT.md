# 안전수칙 (SAFE-OR-NOT) — 먼저 읽으세요

이 키트는 **내부 시스템을 다루기 때문에 특히 조심**해야 합니다.
카드에는 "외부망 개발자가 코드를 짜는 데 필요한 약속"만 적고, **실제 연결 정보는 절대 적지 않습니다.**

---

## ✅ 적어도 되는 것 (약속 — 비밀 아님)

- 시스템 별칭(이름표): `messenger`, `file-transfer`
- 기능 이름: `send_direct_message`
- 무엇을 넣고 무엇이 나오는지 (항목 이름·형식·설명)
- 가능한 오류 코드와 그 뜻
- 속도/재시도 약속: `timeout_ms: 3000`, `retry_max: 2`
- 관리 담당 **역할 이름**: `내부플랫폼팀`

---

## ❌ 절대 적으면 안 되는 것 (실제 연결 정보)

- 실제 서버 **주소(IP·URL)·서비스 경로** (예: `http://10.x.x.x/...`, `/HMemoService`)
- 접속 **코드·열쇠값·비밀번호·인증서·토큰**
- 실제 **직원 식별값·사번·이름·조직도**
- **고객·계좌·거래** 정보 (실제든 예시든)
- 내부 시스템의 **구성도·연결 구조 상세**

> 핵심: **"이걸 외부망에서 누가 봐도 그 시스템에 실제로 접속할 수 없어야 한다."**
> 접속에 필요한 정보가 한 조각이라도 들어가면 안 됩니다.

---

## 쪽지 예시로 감 잡기

| 쓰려는 내용 | 판단 |
|---|---|
| `send_direct_message` (기능 이름) | ✅ 안전 |
| `recipientId / title / body` (항목) | ✅ 안전 |
| `RECIPIENT_NOT_FOUND` (오류) | ✅ 안전 |
| 실제 쪽지 서버 주소나 서비스 경로 | ❌ 금지 |
| 발신 서버 등록 IP, 접속 코드 | ❌ 금지 |
| 실제 받는 사람 사번 목록 | ❌ 금지 |

이 카드를 채운 뒤 `gates/check-no-internal-secrets.sh` 로 검사하면,
실수로 주소·비밀번호가 섞였는지 자동으로 잡아 줍니다.
