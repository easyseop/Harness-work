# 검증 기준 — 출처 구분 (문서근거 vs 우리가 만든 것)

> 솔직 고지용. 행내 문서에서 **근거가 명확한 것**과 **우리가 채운 대표값(mock)·설계 결정**을 분리.
> 참조 문서: ① 데이터모델 설계지침 · ② 상시검토 가이드 · ③ 데이터표준 설계지침 · ④ 명명규칙 PPTX · ⑤ 인스턴스코드 정의서

범례: ✅ 문서 출처 명확 / 🟡 개념은 문서·구체값은 mock / 🔴 우리가 만든 것(mock·조직결정·설계)

---

## A. 테이블/컬럼 명명 — 개념·규칙

| 기준 | 구분 | 출처 / 비고 |
|---|---|---|
| 테이블명 구조 `T+시스템(H/S)+앱(3)+소그룹(2)+일련(2)`=9자 | ✅ | ④ 명명규칙, ② |
| 컬럼은 **인포타입(도메인)으로 끝남** | ✅ | ④ PPTX |
| 인포타입 = **도메인 + 길이**(복수 허용) | ✅ | ③, ④ |
| 컬럼 = `[수식어]+[도메인 끝말]` | ✅ | ③, ④ |
| 한글 컬럼명 사용(영문 전용 아님) | ✅ | 행내 표준(한글명) |
| 한글명 길이 Server 15 / Host 10자(30byte) | 🟡 | 길이 개념은 문서, 정확 수치는 확인 필요 |
| 끝자리 숫자 **허용** | 🔴 | ② 가이드는 '금지' → **우리가 허용으로(조직결정 스위치)** |
| 영문변수명 = **camelCase(첫글자 소문자)** | 🔴 | **사용자/조직 결정** (문서 출처 아님) |
| 한글↔영문 = 표준단어 영문약어 조합 | 🟡 | 조합 개념은 ③, 정확 변환규칙은 DA 확인 필요 |

## B. 코드값(목데이터) — 실제 등록목록으로 교체 필요

| 기준 | 구분 | 출처 / 비고 |
|---|---|---|
| 앱코드 13개(DPS/LON/CUS…) | 🔴 | **mock** — 실제 표준 등록목록 필요 |

| 표준단어 한글 목록(고객·계좌·상태…) | 🟡 | 단어 자체는 통용, **표준단어 등록목록 대조 안 됨** |
| 표준단어 **영문약어값**(CUST·SEX·ACCT…) | 🔴 | **mock** — 실제 영문약어 등록목록 필요 |
| 시스템구분 H=Host/S=Server | ✅ | ④ (H/S 구분) |

## C. 도메인 사전

| 기준 | 구분 | 출처 / 비고 |
|---|---|---|
| 도메인 그룹 9개 체계 | ✅ | 문서 기반 |
| 도메인명(성별·년월일·금액·번호·구분코드…) | ✅ | 문서에 등장하는 도메인명 |
| 금액 길이 15·18.3 | ✅ | 문서 근거 |
| 그 외 도메인 길이값(성별1, 구분코드1/2/3, 명 50/100/200, 일시 14/20 등) | 🟡 | 일부 문서·일부 **mock** (등록목록 대조 필요) |
| 영문약어(DV_CD·CLS_CD·NM·AMT…) | 🔴 | **mock** — 도메인 영문약어 등록목록 필요 |
| 성별 valid_values [1,2], 여부 [0,1] | 🟡 | 통념이나 등록목록 확인 필요 |
| 끝말 예외 `구분 → 구분코드` | 🔴 | **우리 추론**(편의) |

## 한 줄 요약
- **✅ 명확(개념·규칙)**: 테이블명 구조, 인포타입=도메인+길이, 컬럼 도메인 종료, PK/M:N/속성-도메인, 단독금지 12단어, 도메인 그룹9·도메인명·금액 길이, 2시트 구조.
- **🔴 우리가 만든 것**: 앱/소그룹 코드값, 모든 영문약어값, camelCase 규칙, 끝자리숫자 허용, 표준/비표준 판정 메커니즘, 끝말예외.
- **🟡 개념은 문서·값은 확인 필요**: 한글길이 수치, 도메인 길이값 대부분, 끝말 목록, 코드값 통념.

→ **DA에 받을 것**: 표준단어/도메인 **영문약어 등록목록**, 앱·소그룹 코드 등록목록, 한글길이·도메인 길이 확정값, 영문규칙(camelCase) 승인.
