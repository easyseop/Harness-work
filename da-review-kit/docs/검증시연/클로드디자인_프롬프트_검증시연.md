## 프롬프트 (복사해서 사용)

너는 금융권 공식 보고자료 디자이너야. **DA검토 자동화 하네스**의 **실제 검증 시연** PPT(16:9)를 만들어줘.
규칙·예시·결과 문구는 첨부 `전체케이스_카탈로그.md` 그대로 쓰고(변경 금지), **디자인·배치·도식화만** 해.

### 핵심 메시지
"사용자가 `/da-start` 한 번 치면 → 무엇을 검토할지 고르고 → 자유양식 설계도가 자동으로 표준 검사되어 → 통과/반송(사유)이 나온다. 판정은 결정적(LLM 미사용)."

### 대상/톤
- 대상: DA 담당자·데이터 표준 검토자(비개발자 포함), PM.
- 톤: 신뢰감 있는 금융권 공식 보고. 근거 중심, 과한 장식 금지.

### ★ 영문변수명 규칙 (반드시 반영)
- 영문 컬럼/변수명 = **camelCase, 첫글자 소문자**. 예: 고객성별 → `custSex`, 시스템최종처리일시 → `sysLstPrcDtm`.
- 첨부에 옛 표기(`CUST_SEX` 등 대문자_스네이크)가 보이면 **모두 camelCase로 바꿔** 표기할 것.

### 슬라이드 구성
1. **표지** — "DA검토 하네스 — /da-start 검증 시연" + 한 줄 가치.
2. **이 자료는 무엇인가** — 시연 목적 · 결정적 특성 · 메타는 대표 mock.
3. **실행 흐름 (/da-start)** — 아래 4단계를 **세로 스텝/스크린샷 흐름**으로 (실제 동작 순서):
   1) **자기소개** — "저는 DA검토 하네스입니다… 자유양식 원본 → INPUT 변환 → 게이트(결정적 검사) → 통과/반송+사유"
   2) **검토 대상 3지선다** — `DB설계도`(input/freeform/ddl·text) / `인스턴스코드`(input/freeform/instance) / `모두`
   3) **파일 선택** — 후보 파일 나열 + 표준테이블(standard-tables.yaml: TSDPSAA01·TSCRDBB01·TSCUSCA01) 안내
   4) **검토 결과 요약** — 게이트별 통과/반송 + violation 표(대상·사유·권고) + 경고
4. **검사 기준이 되는 메타(표준) 핵심값** — 명명규칙 `^T[HS][A-Z]{3}[A-Z]{2}[0-9]{2}$`, 앱코드(DPS/LON/CUS…), 소그룹(AA/AB…), 도메인(성별·년월일·금액·일시·번호·구분코드…), 표준단어(고객→CUST, 성별→SEX, 계좌→ACCT…), 영문규칙 camelCase.
5. **정상 흐름 예시 (초록)** — `ddl1_고객.sql`(자유 DDL) → 변환(`custNo·custSex·custNm·baseYmd…`) → ✅ 통과.
6. **반송 흐름 예시 (빨강)** — `ddl2_대출.sql` → ❌ 반송: 테이블명 `TXLONBA01` 규칙위반 · 인포타입 `금액99` 비허용 · `임시메모` 도메인 미종료 (+감사컬럼 경고). before/after 대비 카드.
7. **반송 흐름 예시 2 (빨강)** — `ddl4_외환.sql` → ❌ `custGender` 불일치(기대 `custSex`) · PK 미설정. **camelCase 일치 검사 강조**.
7-1. **인스턴스코드 시연 — 정상 (초록)** — `ic1_계좌상태.md`(2시트 표형식) → 변환 → ✅ 통과. 시트1 `계좌상태구분코드`·`신용여부`, 시트2 코드값(0=해당무/1정상/2휴면/3해지, 여부 0/1).
7-2. **인스턴스코드 시연 — 반송 (빨강)** — 실제 반송 사유 그대로:
   - `ic2_명명위반.md` → ❌ 3건: `[임시구분코드] 수식어 '임시' 비표준` · `[여부] 단독사용금지 단어` · `[계좌상태] 끝말 규칙 위반(~구분코드/~코드/~여부/~유무)`
   - `ic4_코드값위반.md` → ❌ 2건: `[거래여부] ~여부 는 코드값 0/1 만 허용 (현재 ['0','1','2'])` · `[유령구분코드] 시트2 인스턴스명이 시트1에 없음`
8~11. **★ 잡을 수 있는 모든 케이스 (29종)** — `전체케이스_카탈로그.md` 표를 그대로 카드/표로. 한 슬라이드에 다 안 들어가면 **그룹 분할**(내용 삭제 금지):
   - (8) 1단계 테이블명 P1~P4
   - (9) 1단계 컬럼·인포타입 P5~P14
   - (10) 1단계 구조·관계·속성 P15~P19 + A1~A4
   - (11) 2단계 인스턴스코드 I1~I11
   각 행: 검사항목 · 유형(🔴차단/🟠경고/⚪건너뜀) · 정상예(초록) · 오류예(빨강) · 결과사유.
12. **유형·한계 (정직 고지)** — 유형 뱃지 설명 + "메타는 대표 mock, 코드↔인스턴스코드 연결은 추가 예정, 값(데이터) 검사는 품질 하네스 별도".
13. **요약** — 한 줄 + DA 확인 포인트(영문규칙 camelCase 확정·표준 등록목록 제공).
