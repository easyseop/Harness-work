# build-provenance 하네스 매뉴얼 (처음 보는 사람용)

> 모르는 용어는 `core/GLOSSARY.md`(용어풀이)를 함께 보세요.

---

## 1. 이 하네스가 왜 있나 (비유로)

물건에 붙는 **제조 이력표(언제·어디서·무엇으로 만들었나)** 와 같습니다.

- **출처(provenance)**: 이 결과물이 어떤 소스로, 누가, 언제 만들어졌는지 기록
- **재현성(reproducible)**: 같은 입력으로 다시 만들면 **똑같은 결과**가 나오는지 확인

외부망에서 만든 것을 내부망에서 다시 빌드했을 때 결과가 같아야, "외부망에서 몰래 다른 게
섞이지 않았다"를 증명할 수 있습니다.

---

## 2. 안 쓰면 무슨 일이 나나 (실패 사례)

- 결과물만 있고 "어떤 소스로 만들었는지" 기록이 없어, 문제 생겨도 **추적 불가**.
- 의존성 버전을 고정(잠금)하지 않아, 빌드할 때마다 다른 버전이 섞임 → 환경마다 다르게 동작.
- 외부망 빌드와 내부망 빌드 결과가 다른데 그냥 넘어감 → **무엇이 들어간 건지 아무도 모름**.

이 하네스는 출처를 강제로 남기고, 내부망 재빌드 결과가 같은지 대조합니다.

---

## 3. 실제 예시로 따라가기

`provenance.messenger.example.yaml` 은 메신저 모듈의 빌드 이력표입니다.

| 항목 | 예시 |
|---|---|
| source_ref | v1.0.0 (어떤 소스로 빌드) |
| built_by / built_on | CI-빌드시스템 / 2026-06-16 |
| inputs_hash | 입력의 지문 |
| output_hash | 결과물의 지문 |
| lockfile / sbom | poetry.lock / sbom.spdx.json |
| rebuilt_output_hash | 내부망 재빌드 결과 (output_hash 와 동일 ✔) |

```bash
gates/check-provenance-complete.sh provenance.messenger.example.yaml
gates/check-reproducible.sh        provenance.messenger.example.yaml
```

음성 예) 재빌드 해시가 다르면 → "재현성 실패" 로 막힘.
SBOM 이 없으면 → "구성요소 목록 누락" 으로 막힘.

## 4. 내가 직접 할 일 vs 자동으로 되는 일

| 구분 | 누가 | 무엇을 |
|---|---|---|
| 🟡 자동(빌드도구) | 빌드 시스템 | 해시·잠금파일·SBOM 생성 |
| 🟡 직접 | 빌드 담당 | 그 결과를 `provenance.yaml` 로 정리 |
| 🔴 내부망 | 내부 담당자 | 재빌드 후 `rebuilt_output_hash` 채우기 |
| 🟢 자동 | 게이트 | 출처 완결성·재현성 자동 검사 |

> 핵심: 해시는 빌드 도구가 만들어 줍니다. 당신은 그걸 **정리해서 적기만** 하면 됩니다.

## 5. 자주 막히는 곳 (FAQ)

**Q. 해시(hash)가 뭔가요?**
A. 파일의 "지문"입니다. 내용이 1글자라도 다르면 지문이 완전히 달라집니다.
그래서 두 빌드 결과가 같은지 비교할 때 씁니다. 빌드 도구가 자동으로 만들어 줍니다.

**Q. 재빌드를 아직 안 했어요.**
A. `rebuilt_output_hash` 가 비어 있으면 재현성 게이트는 "아직 미확인"으로 통과를 보류합니다.
내부망 reproduce 단계에서 채운 뒤 다시 검사하면 됩니다.

**Q. 잠금파일(lockfile)이 왜 필요한가요?**
A. 의존성 버전을 고정해야 "같은 입력 → 같은 결과"가 보장됩니다. 잠금이 없으면 빌드마다
버전이 달라질 수 있습니다.

**Q. 재현성이 안 맞으면요?**
A. 보통 잠금파일·빌드환경(시각·경로 등) 차이입니다. 원인을 맞춰야 통과합니다
(임시로는 만료 있는 waiver).
