# 안전수칙 (SAFE-OR-NOT) — 먼저 읽으세요

이 키트의 어떤 파일에도 **민감정보를 적으면 안 됩니다.**
여기 적는 건 "정책 사실"이지 "내부 비밀"이 아닙니다.

---

## ✅ 적어도 되는 것 (정책 사실 — 비밀 아님)

- 허용 언어/프레임워크 이름과 버전 (예: `java-21`, `n-framework`)
- 산출물 형태 (`jar`, `컨테이너`)
- 배포환경 종류 (`온프레미스`, `kubernetes`, `레거시-WAS`)
- 차단/검토 라이선스 이름 (`AGPL-3.0`)
- 취약점 차단 등급 (`critical`, `high`)
- 반입 방식 종류 (`소스반입`)
- 승인 **역할/팀 이름** (`보안검토위원회`, `변경관리팀`)
- 내부 솔루션의 **별칭** (`messenger`, `file-transfer`) — 이름표 수준만

---

## ❌ 절대 적으면 안 되는 것 (민감정보)

- 실제 서버 **IP / hostname / URL** (예: `10.x.x.x`, `mq.internal.bank`)
- **token / secret / 비밀번호 / 인증서 / 키**
- 실제 **직원 이름 / 사번 / 조직도**
- **고객 / 계좌 / 카드 / 거래** 데이터 (실제든 샘플이든)
- n/z/u 같은 **코어뱅킹 프레임워크의 내부 소스나 상세 규칙 원문**
- 내부망 **구성도 / topology / 방화벽 규칙**
- vendor 제품의 **반출 금지 설정 원문**

---

## 헷갈릴 때 판단 기준 (한 문장)

> **"이 줄이 외부에 유출돼도 보안사고가 아닌가?"**
> 아니라고 자신 있으면 적어도 되고, 조금이라도 망설여지면 적지 말고 담당자에게 물어보세요.
