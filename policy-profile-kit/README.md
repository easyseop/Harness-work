# policy-profile 채우기 키트

이 폴더는 MVP 1번 하네스 **policy-profile**(분류·허용스택)를 완성하기 위한 "채우기 키트"입니다.
개발 지식이 깊지 않아도 **빈칸 양식에 값만 채우면** 되도록 구성했습니다.

## 이 하네스가 하는 일 (한 줄)

> 개발을 시작하기 *전에*, "이게 뭔지(분류)"와 "우리가 뭘 써도 되는지(허용 범위)"를 먼저 못 박는다.
> 여기가 틀리면 외부망에서 만든 코드가 내부망에 안 맞아서 나중에 크게 고쳐야 한다.

## 폴더 안에 뭐가 있나

| 파일 | 색 | 누가 채우나 | 설명 |
|---|---|---|---|
| `policy.yaml` | 🟡 | **당신/내부담당자** | "우리가 허용하는 언어·프레임워크·라이선스" 등 정책 값 |
| `profile.schema.json` | 🟢 | 제가 완성 | 채운 값의 형식이 맞는지 자동 검사하는 규칙 |
| `profile.example.json` | 🟢 | 제가 완성(예시) | "프로젝트 1건"을 분류하면 이런 결과가 나온다는 샘플 |
| `gates/check-classification-complete.sh` | 🟢 | 제가 완성 | 분류 빈칸이 남았는지 검사 |
| `gates/check-allowed-tech-stack.sh` | 🟢 | 제가 완성 | 요청 스택이 허용목록 안인지 검사 |
| `manifest.yaml` | 🟢 | 제가 완성 | 이 하네스를 Spine에 등록하는 명세 |
| `FILL-GUIDE.md` | 🟢 | (읽기용) | **빈칸 채우는 설명서** — 먼저 읽으세요 |
| `SAFE-OR-NOT.md` | 🔴 | (읽기용) | **안전수칙** — 적어도 되는 것 / 절대 안 되는 것 |

## 쓰는 순서

```text
1. SAFE-OR-NOT.md 를 먼저 읽는다   (무엇을 적으면 안 되는지)
2. FILL-GUIDE.md 를 보며           (각 칸에 뭘 적는지)
3. policy.yaml 의 TBD 빈칸을 채운다
4. 게이트를 돌려 빈칸/오류가 없는지 확인한다
```

## 용어 미리 풀이 (개발 안 해도 이해되게)

- **policy(정책)**: "우리 조직이 허용/금지하는 규칙 목록". 예) "자바 21은 OK, AGPL 라이선스는 금지".
- **profile(프로파일)**: "프로젝트 1건을 분류한 결과표". 예) "이건 배치 프로그램이고, 자바로 만들고, 온프레미스에 올라간다".
- **gate(게이트)**: "통과/실패를 자동으로 판정하는 검사". 사람이 매번 눈으로 확인하지 않게 함.
- **schema(스키마)**: "값이 올바른 형식인지 검사하는 틀". 빈칸·오타를 잡아줌.
- **manifest(매니페스트)**: "이 하네스가 자기를 소개하는 명함". Spine은 이것만 보고 하네스를 부름.
