# 안전수칙 (SAFE-OR-NOT) — import-gate

반입 묶음은 여러 증거를 모으는 곳이라, 실제 민감정보가 섞여 들어오지 않게 조심합니다.

---

## ✅ 적어도 되는 것

- 프로젝트 식별값·버전·작성일
- 구성요소 **경로** (`src/`, `poetry.lock`, `sbom.spdx.json`)
- 증거 id 와 상태 (`profile : passed`)
- 책임 **역할** 이름 (`개발팀-A`, `반입승인책임자`)
- 예외 승인 내용 (게이트명·사유·승인역할·만료일)

---

## ❌ 적으면 안 되는 것

- 실제 HOST·IP·URL·SRV_CODE 값 (묶음에도 절대 X — 내부망 주입)
- 비밀번호·토큰·인증서 내용
- 실제 직원 **이름·사번** (역할명으로 대체)
- 고객정보·개인정보

> 핵심: 묶음은 "무엇이 들어있고 누가 책임지는지의 **목록**"입니다.
> 민감한 **실제 값**은 묶음 안에도 두지 않습니다.

## 게이트가 지켜 줍니다

- `check-bundle-complete` — 구성요소 누락·증거 미통과 시 차단 (우회 불가)
- `check-roles-and-waivers` — 만든 사람=승인자거나, 예외가 만료/무기한이면 차단 (우회 불가)

## 한 가지 더 — 역할 분리는 사람 보호 장치

만든 사람과 승인자를 나누는 건 누구를 못 믿어서가 아니라, **혼자 책임지지 않게** 하는
보호 장치입니다. 사고가 나도 견제 기록이 남아 모두를 보호합니다.
