# oss-runtime-eol 하네스 매뉴얼 (처음 보는 사람용)

> 모르는 용어는 `core/GLOSSARY.md`(용어풀이)를 함께 보세요.

---

## 1. 이 하네스가 왜 있나 (비유로)

식재료의 **유통기한과 원산지 표시**를 확인하는 것과 같습니다.

- **라이선스 확인**(원산지): 이 오픈소스를 우리가 써도 되는 조건인지
- **수명(EOL) 확인**(유통기한): 이 런타임/라이브러리가 더는 보안 업데이트를 안 받는
  "수명종료" 상태는 아닌지

기한이 지난 재료를 쓰면 탈이 나듯, EOL 런타임은 보안 구멍이 생겨도 패치가 안 나옵니다.

---

## 2. 안 쓰면 무슨 일이 나나 (실패 사례)

- 금지 라이선스(예: AGPL) 라이브러리를 모르고 썼다가, 반입 직전 또는 감사에서 걸림 → 전면 교체.
- 이미 수명종료된 런타임(예: 오래된 파이썬)을 쓰다가, 새 취약점이 나와도 **패치가 없어** 방치.
- "곧 EOL"인 걸 몰라서, 운영 중에 갑자기 지원이 끊김.

이 하네스는 위를 **반입 전에** 잡고, EOL 임박은 미리 경고합니다.

---

## 3. 실제 예시로 따라가기

`components.messenger.example.yaml` 은 메신저 모듈이 쓰는 구성요소 목록입니다.

| 구분 | 예시 | 판정 |
|---|---|---|
| 런타임 | java 21 (EOL 2031) | ✅ 수명 충분 |
| 라이브러리 | spring-boot (Apache-2.0) | ✅ 허용 라이선스 |
| 라이브러리 | http-client (MIT) | ✅ 허용 |

```bash
gates/check-license.sh components.messenger.example.yaml
gates/check-eol.sh     components.messenger.example.yaml policy.yaml 2026-06-16
```

음성 예) AGPL 라이브러리를 넣으면 → "금지 라이선스" 로 막힘.
EOL 지난 python 3.8 을 넣으면 → "이미 수명종료" 로 막힘.

## 4. 내가 직접 할 일 vs 자동으로 되는 일

| 구분 | 누가 | 무엇을 |
|---|---|---|
| 🟡 직접 | 개발자 | 쓰는 구성요소를 `components.yaml` 에 적기 (또는 SBOM 변환) |
| 🟡 직접 | 거버넌스팀 | `policy.yaml` 의 허용/금지 라이선스·런타임 EOL 날짜표 관리 |
| 🟢 자동 | 게이트 | 라이선스 위반·EOL 자동 검사, 임박 경고 |

> 핵심: 라이선스 허용목록과 EOL 날짜표는 **조직 공용**입니다. 한 번 잘 만들어 두면
> 모든 프로젝트가 같은 기준으로 검사됩니다.

## 5. 자주 막히는 곳 (FAQ)

**Q. EOL 날짜는 어떻게 아나요?**
A. 런타임 공식 지원종료(End-of-Life) 일정을 `policy.yaml` 의 `runtimes` 표에 적어 둡니다.
공개 EOL 정보 사이트나 벤더 공지를 참고해 거버넌스팀이 관리합니다.

**Q. 허용목록에 없는 라이선스를 만나면요?**
A. `unknown_action` 이 `block` 이면 막고, `warn` 이면 경고만 합니다. 기본은 block(안전).

**Q. 곧 EOL인데 당장 못 바꿔요.**
A. `warn_within_days`(기본 180일) 안이면 경고만 뜨고 반입은 됩니다. 이미 지난 건 막힙니다
(필요 시 만료 있는 waiver).

**Q. SBOM 이 뭔가요?**
A. "이 소프트웨어에 무슨 구성요소가 들어있나"의 목록입니다. 의존성 도구가 만들어 주며,
그 결과를 `components.yaml` 형식으로 옮기면 됩니다.
