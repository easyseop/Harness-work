# deploy-runbook 하네스 매뉴얼 (처음 보는 사람용)

> 모르는 용어는 `core/GLOSSARY.md`(용어풀이)를 함께 보세요.

---

## 1. 이 하네스가 왜 있나 (비유로)

비행기 조종사의 **체크리스트**와 같습니다.
"이륙 전 무엇을 확인하고, 어떤 순서로 하고, 문제가 생기면 어떻게 되돌리는지"를
빠짐없이 적어 둡니다.

이 하네스는 내부망 배포 절차를 안내서(runbook)로 표준화합니다.

- **precheck**(사전점검) → **deploy**(배포) → **verify**(검증) → **rollback**(되돌리기) → **contacts**(비상연락)

특히 **롤백(되돌리기)이 없으면 배포 자체를 막습니다** — 되돌릴 방법 없는 배포는 위험하니까요.

---

## 2. 안 쓰면 무슨 일이 나나 (실패 사례)

- 배포는 했는데 **검증 단계가 없어** 문제를 한참 뒤에 발견.
- **롤백 절차가 없어**, 장애가 나도 못 되돌리고 손 놓음.
- 안내서에 실제 서버 주소·접속코드를 적어 둬서 **민감정보 유출**.
- 비상 연락이 특정 개인 이름이라, 그 사람이 자리 비우면 마비.

이 하네스는 위 단계가 다 있는지, 비밀값이 안 섞였는지 검사합니다.

---

## 3. 실제 예시로 따라가기 (메신저 사례)

`runbook.messenger.example.yaml` 은 메신저 모듈 배포 안내서입니다.

| 단계 | 예시 내용 |
|---|---|
| precheck | 반입 통과 확인 / 설정 빈 자리 주입 확인 / 발신 IP 등록 확인 |
| deploy | 산출물 배치 → 설정 주입 → 재기동 → 로그 확인 |
| verify | 헬스체크 / 테스트 쪽지 결과코드 0 확인 / 오류처리 확인 |
| rollback | 신규 중지 → 직전 버전 복원 → 복구 확인 → 통지 |
| contacts | 운영팀 당직 / 내부플랫폼팀 / 반입승인책임자 (모두 역할) |

```bash
gates/check-runbook-complete.sh      runbook.messenger.example.yaml
gates/check-no-secrets-in-runbook.sh runbook.messenger.example.yaml
```

음성 예) 롤백을 비우면 → "되돌릴 방법 없는 배포 금지" 로 막힘.
실제 IP를 적으면 → "실제 값(민감정보)" 으로 막힘.

> 실제 HOST·SRV_CODE 는 안내서에도 적지 않습니다. 빈 자리(설정 주입)와 역할로만 적습니다.

---

## 4. 내가 직접 할 일 vs 자동으로 되는 일

| 구분 | 누가 | 무엇을 |
|---|---|---|
| 🟡 직접 | 운영/배포 담당 | `runbook.yaml` 에 단계별 절차 적기 |
| 🟢 자동 | 게이트 | 필수 단계·롤백·검증 유무, 비밀값 섞임 자동 검사 |

> 핵심: 절차를 "사람 머릿속"이 아니라 **문서로** 남기는 게 목적입니다.
> 누가 배포해도 같은 순서로, 문제 시 같은 방법으로 되돌릴 수 있게요.

## 5. 자주 막히는 곳 (FAQ)

**Q. 롤백 절차를 꼭 적어야 하나요?**
A. 네. `require_rollback` 이 켜져 있어 롤백이 비면 막힙니다. 되돌릴 방법 없는 배포는 금지입니다.

**Q. 실제 서버 주소를 적어야 정확하지 않나요?**
A. 아니요. 안내서에도 실제 주소·접속코드는 금지입니다. 빈 자리(`${MESSENGER_HOST}`)와
"설정 주입" 표현으로 적습니다. 실제 값은 내부망 설정에만 있습니다.

**Q. 연락처에 실제 이름·전화번호를 적으면요?**
A. 역할(`운영팀 당직`)로 적습니다. 개인이 바뀌어도 안내서가 유효하고, 개인정보도 보호됩니다.

**Q. 이 하네스는 언제 도나요?**
A. 반입(import-gate) 통과 후, 내부망 배포(reproduce) 단계에서 적용됩니다.
