# 제공 정보 → 하네스 적용 방식 정리

> 담당자가 제공한 정보 하나하나가 품질 하네스에 **어떻게 적용되었는지** 기록.
> 각 항목은 [제공한 것] → [어디에(위치) / 어떻게 강제 / 동작 흐름 / 근거 파일] 순.

---

## ① 테이블 명명규칙

- **제공**: `T + 시스템(D=DW/C=Core/K=그외) + 앱코드3자 + 식별부2자 + 일련번호2자`, 예 `TCABCX901`
- **위치**: `policy.yaml` → `naming.table_pattern`
  - 정규식: `^T[DCK][A-Z]{3}[A-Z][A-Z0-9][0-9]{2}$`
- **강제**: `check-naming` 게이트가 테이블명을 이 정규식과 대조. 안 맞으면 **차단(exit 1)**.
- **흐름**: 계약서 등록 → 이름이 패턴에 맞으면 통과, 틀리면 위반 메시지 출력 후 실패.
- **근거**: `gates/check-naming.sh`, 테스트 `bad-naming.yaml`(소문자 이름 → 정상 차단)

## ② 컬럼 명명규칙 — "없음"

- **제공**: 컬럼명 규칙은 정해져 있지 않음.
- **위치**: `policy.yaml` → `naming.column_pattern: ""` (빈 값)
- **강제**: 빈 값이면 컬럼명 검사를 **건너뜀**. (이름 대신 아래 ③ 값 검사로 품질 확보)

## ③ 컬럼 값 검사 — 년월일8 / 인스턴스 유효식별자  ★핵심

- **제공**:
  - "타입이 년월일8이면 유효한 YYYYMMDD 형식이어야 함"
  - "인스턴스 식별자 컬럼은 유효식별자 목록 값만 허용, 예 [1,2,3,4] 인데 0 들어오면 오류"
- **위치**:
  - 규칙 선언: 각 계약서의 컬럼 (`type: date8`, `valid_values: [...]`, `instance_identifier: true`)
  - 검사 동작: `gates/check-data-values.sh` + `policy.yaml`의 `value_rules`
- **강제**: 실제 데이터(CSV)의 모든 행·셀을 검사. 위반 1건이라도 있으면 **차단(exit 1)**.
  - date8 → 8자리 + 실제 달력 날짜 (13월·32일·7자리 = 오류)
  - valid_values → 목록 밖 값 = 오류 (0 = 오류)
- **흐름**: 개발자가 I/O 데이터를 적재하기 전 게이트 실행 → 유효값만 통과 → "유효값이 들어오도록 조건처리"를 안 하면 빌드/배포가 막힘.
- **근거**: 데모에서 `20261301`(13월), `2026011`(7자리), `0`(식별자) 모두 검출. 테스트 `good.yaml + sample-bad.csv → 정상 차단`.

## ④ 표준 / 비표준 DB(테이블) — 값 검사 적용 범위

- **제공**: "값 기준은 표준 DB(테이블)에만 해당. 사전에 표준/비표준 여부를 물어봐야 함."
- **설계 원칙**: 표준/비표준은 하네스 전체 스위치가 **아님**. 테이블 A는 표준, B는 비표준일 수 있으므로 **테이블마다** 갖는 속성.
- **위치(앞단)**: 각 테이블 계약서의 `dataset.standard: true/false`
  - = 그 테이블을 등록하는 "앞단"에서 개발자가 반드시 적는 값.
- **강제**: `standard` 를 **필수 메타데이터**로 지정 → 안 적으면 메타검사 자체가 **실패**.
  - → "표준인지 비표준인지 안 정하고 넘어가는 일"을 원천 차단.
- **흐름**: 베이스 하네스가 테이블 등록 시 `standard` 를 반드시 받음 →
  - `true` 면 ③ 값 검사 **강제**
  - `false` 면 값 검사 **건너뜀(통과)**
- **근거**: `gates/check-data-values.sh`(맨 앞 표준 판정), `required_metadata: standard`,
  테스트 `nonstandard.yaml + sample-bad.csv → 건너뜀(통과)`, `standard 누락 → 메타검사 실패`.

## ⑤ 필수 메타데이터

- **제공**: "반드시 적을 것: 테이블명·스키마명·테이블정의(+컬럼정의). 책임역할·보관기간은 강제 아님."
- **위치**: `policy.yaml` → `required_metadata: [standard, schema, description]`
  - 테이블명은 명명규칙(①)으로 별도 강제, 표준여부(④)도 필수에 포함.
- **강제**: 누락/미정(빈칸·"미정"·"TBD")이면 `check-metadata-complete` 가 **차단**.
- **근거**: `gates/check-metadata-complete.sh`, 테스트 `bad-tbd.yaml`.

## ⑥ 데이터 등급(보안 분류) — "없음"

- **제공**: "별도 등급 체계 없음. 내부망 관리, 조회권한 신청 기반."
- **위치**: `policy.yaml` → `allowed_classifications: []` (빈 목록)
- **강제**: 빈 목록이면 등급 검사를 **건너뜀**. (옛 등급 기본값·픽스처는 제거함)

## ⑦ 데이터 흐름(lineage) — "안 씀"

- **제공**: 출처→사용처 기재 안 함.
- **위치**: `policy.yaml` → `require_lineage: false`
- **강제**: 검사 안 함. (옛 lineage 픽스처·케이스 제거함)
