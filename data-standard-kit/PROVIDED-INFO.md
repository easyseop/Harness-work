# 데이터 표준(품질) 하네스 — 제공받은 정보 정리

> 담당자가 제공한 실제 정보를 모은 것. policy.yaml 을 채우는 근거 자료.
> (확정되지 않은 항목은 ❓ 로 표시 — 추가 확인 필요)

---

## 1. 테이블 명명규칙  ✅ 제공됨

형식: **`T + E + xxx + cc + nn`** (총 9자, 영문 대문자·숫자)

| 자리 | 길이 | 뜻 | 값 |
|---|---|---|---|
| ① T | 1 | 테이블 표시 (고정) | `T` |
| ② system 구분 | 1 | 시스템 구분 | `D`(DW) / `C`(Core) / `K`(그 외) |
| ③ 어플리케이션코드 | 3 | 업무별 앱코드 (대문자) | 예: `ABC` |
| ④ 식별부 | 2 | 랜덤 알파벳+숫자 **또는** 알파벳 2자 | 예: `X9`, `AB` |
| ⑤ 일련번호 | 2 | 숫자 두 자리 | 예: `01` |

- 예시: `TCABCX901` (T-C-ABC-X9-01)
- 정규식(자동 검사용): `^T[DCK][A-Z]{3}[A-Z][A-Z0-9][0-9]{2}$`

## 2. 데이터 보안 등급  ✅ 제공됨 → "별도 등급 없음"

- 별도 등급 체계를 쓰지 않음. 내부망에서만 관리.
- 접근은 **조회권한 신청** 기반 (등급으로 나누지 않음).
- → 정책에서 **등급 필수/검사 제외**.

## 3. 반드시 기재할 항목  ✅ 확정

- 필수: **표준여부(standard)**, **스키마명(schema)**, **테이블 정의(description)**
- 강제 안 함: 책임역할·보관기간·등급 (조직에 등급 체계 없음)

## 4. 컬럼 값 검사 규칙  ✅ 제공됨 (← 하네스의 핵심)

컬럼명 규칙은 없음. 대신 **컬럼 값이 유효한지** 검사한다:

- **type = date8 (년월일8)**: 값이 유효한 `YYYYMMDD` 여야 함.
  - 잡아냄: `20261301`(13월), `2026011`(7자리) 등
- **인스턴스 식별자 컬럼**: `valid_values` 목록(인스턴스 유효식별자)에 있는 값만 허용.
  - 예: `valid_values: [1,2,3,4]` 인데 `0` 들어오면 오류
- 개발 단계 강제: 이 검사를 CI/배포 전에 돌려 위반 시 **실패(차단)**.

## 5. 표준 / 비표준 DB(테이블)  ✅ 확정

- 값 검사 기준은 **표준 테이블에만** 적용.
- 표준/비표준은 테이블마다 다른 속성 → 각 계약서 `dataset.standard: true/false` 에 둠.
- 이 값은 **필수**(안 적으면 검사 실패) → 표준여부 미결정 상태로 넘어가는 것 차단.
- `standard: true` → 값 검사 강제 / `false` → 값 검사 건너뜀.
