# 안전수칙 (SAFE-OR-NOT) — data-standard

데이터 표준 정보는 대부분 안전하지만, **실제 데이터 값**이 섞이지 않게 조심합니다.

---

## ✅ 적어도 되는 것 (구조·표준 정보)

- 테이블/컬럼 이름, 자료형 (`account_id`, `decimal`)
- 표준 용어 (`계좌식별자`, `잔액`)
- 데이터 등급, 보관 기간, 설명
- 책임 **역할** 이름 (`데이터플랫폼팀`)
- 흐름(lineage): 출처/사용처 데이터셋 이름

---

## ❌ 적으면 안 되는 것 (실제 데이터·민감정보)

- **실제 데이터 값** (실제 계좌번호·잔액·고객명 등) — 설명이나 예시에도 X
- 실제 **접속 정보**(DB 주소·계정·비밀번호)
- 실제 **직원 이름·사번**
- 주민등록번호·카드번호 같은 개인정보

> 핵심: 여기 적는 건 "데이터의 **설계도**"이지 "데이터 **내용**"이 아닙니다.
> 설계도(이름·형식·등급·흐름)는 적고, 실제 값은 절대 적지 않습니다.

## 예시로 감 잡기

| 쓰려는 내용 | 판단 |
|---|---|
| `account_id : string : 계좌식별자` | ✅ 안전 (설계도) |
| `balance_amt : decimal : 잔액` | ✅ 안전 |
| 설명에 `예: 110-234-567890, 잔액 1,200,000` | ❌ 금지 (실제 값) |
| `classification: 민감` | ✅ 안전 |
